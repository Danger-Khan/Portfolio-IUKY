Engine: Humanizer

Rewrites stock AI-sounding phrasing.

"In today's fast-paced world," "it is important to note that," "utilize," "seamless" — swapped for plainer, contracted language. Rule-based, not a trained model: every swap it makes comes straight from Humanizer/database.sql, so there's nothing hidden. It also runs the result through the Slicer engine (../Slicer/) for a word-class breakdown and tense detection — Slicer has no page of its own; this is the only place it's used.

Prefer the terminal? echo "your text" | python Humanizer/backend.py from the AI/ML folder runs the identical rule set through backend_pipeline.py and SQLite instead of the browser — useful for batch-processing files. All five options above have CLI flags too: --intensity {light,medium,full}, --length {shorten,normal,extend}, --dialect {us,uk,aus}, --jargon, and --no-fluency. It prints the same Slicer-powered grammar breakdown too, unless you pass --quiet.
What this actually is: fixed lookup tables — phrases, words, contractions, filler terms, transition connectors, US/UK spelling pairs, and jargon terms — all listed in Humanizer/database.sql. "Shorten" deletes known filler words; "Extend" prepends real transition phrases to alternating sentences — it doesn't invent new content. "AUS spelling" reuses the UK table, since Australian English follows British spelling conventions here. It's not a language model and it doesn't understand meaning — it just recognizes specific stock phrasing and swaps it. The grammar breakdown above it comes from the Slicer engine in ../Slicer/ — plain-text lexicons in Slicer/Word Library/, a one-word-of-context disambiguation table, and a 12-tense pattern table, both in Slicer/Grammer Context/. Pattern-matching heuristics, not a real parser — they will get some sentences wrong, and this doesn't hide that. Slicer isn't a page of its own; it only runs here, on whatever the Humanizer just produced.
Engine: Image Extractor

Render text, corrupt a few pixels, read it back.

A small, honest OCR pipeline: your text is drawn with a hand-built 5x7 bitmap font from Image Extractor/Glyph Library/font-5x7.txt, a slider lets you flip a percentage of pixels at random, and a nearest-neighbor classifier (Hamming distance against every known glyph — the templates are the model, no training step needed) reads the result back. The exact same algorithm runs three times over: extractor-engine.js here in the browser, extractor_cli.py in Python, and extractor.pl in Perl — all three reading the one font file directly. Fixed-pitch, single font, single line: this reads text the tool itself rendered, not arbitrary photos.
